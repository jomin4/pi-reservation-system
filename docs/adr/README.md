## ADR과 설계 문서의 경계

| | 설계 문서 (`data.md` · `api.md` …) | **ADR** |
|---|---|---|
| 답하는 질문 | **"지금 어떻게 되어 있나"** | **"왜 그렇게 됐나 · 무엇을 버렸나"** |
| 시제 | **현재형** | **과거형 — 그 시점의 기록** |
| 수정 | 계속 갱신 | **불변. 바뀌면 새 ADR** |
| 충돌하면 | ✅ **이쪽이 이긴다** | 역사 기록일 뿐 |

> **ADR을 불변으로 두면 드리프트가 구조적으로 불가능하다.** ADR이 "현재 상태"를 주장하지 않기 때문이다. 상태 값(`채택`/`대체됨`/`폐기`)만 갱신한다.

## 언제 쓰나

**세 질문에 전부 "예"여야 쓴다.**

| # | 질문 |
|---|---|
| ① | **되돌리기가 비싼가?** |
| ② | **대안을 실제로 저울질했나?** (둘 이상을 비교하고 하나를 버렸다) |
| ③ | **6개월 뒤 "왜 이랬지?"를 물을 것 같나?** |

**안 쓰는 것** — 관례로 정해지는 것(`camelCase`) · 대안이 없던 것 · 코드를 보면 아는 것 · 아직 안 정한 것.

> **한 건에 1~2쪽.** 넘기면 아무도 안 읽는다. 길어지면 결정이 두 개 섞인 것이니 나눈다.

## 쓰는 법

1. [TEMPLATE.md](TEMPLATE.md)를 `NNNN-영문-슬러그.md`로 복사
2. 안내 주석을 지우고 채운다
3. 이 파일의 목록에 한 줄 추가
4. 옛 결정을 뒤집었다면 **그 ADR의 `상태`만** `대체됨 (ADR-NNNN)`으로 바꾼다

**번호는 재사용하지 않는다.**

## 아직 ADR이 없는 확정 사항

기준 ①~③을 다 만족하지는 않아 안 쓴 것들. 근거는 각 설계 문서의 `> **의도**` 블록에 있다.

| 결정 | 근거 위치 |
|---|---|
| 완전 분리 + 매퍼 (도메인 ↔ JPA) | `CLAUDE.md` · ADR-0001에 포함 |
| `TransactionRunner` 포트 | `data.md` §4 |
| RFC 9457 + `code` 확장 | `api.md` §4 |
| ~~`openapi.yaml`~~ | **ADR-0007로 승격** |
| `202 Accepted` + `PAYMENT_PENDING` | `api.md` §4 |
| `COMPLETED`를 저장하지 않고 파생 | `data.md` §5.5 |
| SSE 스트림 비인증 | `api.md` §6.1 |
| `409`는 `INFO` (로그 레벨 정책) | `operate.md` §1 |
| `operate.md` 분리 | `operate.md` 머리말 |
| `fare` 테이블 신설 | `data.md` §3 |
| `trip_seat` 인덱스 최소화 | `data.md` §8.10 |
| Flyway는 스키마만 | `data.md` §9.1 |
| 부하 생성 도구 연기 | `CLAUDE.md` 미확정 |
| 공공데이터 실연동 미채택 | `search/korail-trip-data.md` §6 |

> **이 목록이 길어지면 기준을 다시 봐야 한다.** "되돌리기 비싼 것만"이 "아무것도 안 쓴다"가 되면 ADR을 둔 의미가 없다.
