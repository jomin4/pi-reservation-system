# ADR-0008 — Tailwind 메이저를 웹과 모바일에서 다르게 간다

| | |
|---|---|
| 상태 | 채택 |
| 날짜 | 2026-09-11 |
| 대체 | — |
| 관련 문서 | [tech.md](../tech.md) §프론트 계열 「버전 고정」 · [mobile/CLAUDE.md](../../mobile/CLAUDE.md) |

## 맥락

웹 트랙이 먼저 갔다. 2026-09-11 `tech.md`가 웹 스택을 실측값으로 고정하면서 **`tailwindcss` 4.3.3 · `@tailwindcss/vite` 4.3.3**을 확정했고, 그 값으로 `front/` 스캐폴드가 올라갔다.

그 직후 모바일 스택을 실측하다 막혔다. **`nativewind`의 peer만 보면 4가 되는 것처럼 보인다.**

```
nativewind@4.2.6
  peer: tailwindcss@>3.3.0          ← 4 를 받는 것처럼 읽힌다
  └─ react-native-css-interop@0.2.6
       peer: tailwindcss@~3          ← 실제로는 여기서 막힌다
```

**실제 변환을 하는 건 `nativewind`가 아니라 그 아래 `react-native-css-interop`이다.** 그쪽 peer가 `~3`이라 4를 넣으면 설치 단계에서 갈린다.

그 시점의 숫자:

| 항목 | 값 |
|---|---|
| `nativewind` latest | **4.2.6** (2026-06-22) |
| `nativewind` 다음 메이저 | **`5.0.0-preview.4`** — prerelease 채널만 있다 |
| `tailwindcss` 3.x 마지막 | **3.4.19** (2025-12-10) |
| 웹이 이미 머지한 값 | **4.3.3** |
| `front`/`mobile` 패키지 관리 | **각자 독립.** workspace로 안 묶여 있다 |

마지막 줄이 이 결정을 가능하게 했다. `tech.md`가 **Expo metro resolver 이슈를 피하려고** 이미 workspace 분리를 택해둔 상태였고, 그래서 **두 트랙이 같은 패키지의 다른 메이저를 가져도 물리적으로 충돌하지 않는다.**

## 검토한 대안

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **A. 모바일만 `tailwindcss@3.4.19`** | **둘 다 안정 버전** · 각자 생태계와 정합 | **Tailwind 문법이 트랙마다 다르다** | ✅ **채택** |
| B. NativeWind 5 preview로 모바일도 4 | 문법이 통일된다 | **`preview.4` — prerelease.** 스타일 엔진이 깨지면 원인 추적이 본질(동시성)에서 멀다 | ❌ |
| C. 웹을 3.4.19로 내린다 | 문법이 통일된다 | **이미 머지된 결정을 되돌린다.** `@tailwindcss/vite` 4.3.3도 함께 내려야 하고, 얻는 건 "같아 보인다"뿐 | ❌ |
| D. 모바일 스타일을 `StyleSheet`로 | Tailwind 자체를 안 쓴다 | 웹과 디자인 토큰을 공유할 길이 사라진다 | ❌ |

## 결정

> **웹은 Tailwind 4, 모바일은 Tailwind 3. 맞추지 않는다.**

급소는 **"갈렸다"가 아니라 "갈린 걸 문서에 적었다"**는 쪽이다.

```
front/   tailwindcss 4.3.3   @theme { --color-... }        CSS 우선
mobile/  tailwindcss 3.4.19  tailwind.config.js            JS 설정
```

**두 값이 다른 걸 본 다음 사람의 첫 반응은 "맞춰야겠다"이다.** 그래서 `tech.md`에 ⚠️를 달고 이 ADR을 링크했다. **맞추려는 순간 B나 C로 끌려간다.**

## 결과

| 얻은 것 | 잃은 것 |
|---|---|
| **양쪽 다 안정 버전** — prerelease 의존 0 | **Tailwind 문법이 트랙마다 다르다** (`@theme` vs `tailwind.config.js`) |
| 스타일 문제가 생겨도 **각 생태계의 표준 사례가 그대로 적용된다** | 디자인 토큰을 **두 곳에 따로 쓴다** |
| NativeWind 5 정식판을 **기다렸다 옮길 수 있다** — 강제 시점이 없다 | "웹과 모바일이 같은 스택"이라는 말이 **반쯤만 참이 된다** |

> **잃은 것 중 마지막이 실질적으로 가장 크다.** 이 프로젝트는 "웹·모바일이 같은 API를 쓴다"를 내세우는데, **스타일 계층은 같지 않다.** API 계약은 하나이고 스타일은 둘이다 — 그 경계를 흐리지 않는다.

## 되돌린다면

| 항목 | 비용 |
|---|---|
| 모바일을 4로 올린다 | **NativeWind 5 정식판이 나오면 싸다** — `tailwind.config.js`를 `@theme`로 옮기는 작업 |
| 웹을 3으로 내린다 | 중간 — `@tailwindcss/vite`를 걷어내고 PostCSS 설정을 되살린다 |
| **디자인 토큰을 나중에 공유하려 할 때** | ⚠️ **비싸다** — 양쪽 문법이 다른 상태로 토큰이 굳으면 **공유 지점을 만들 자리가 없다** |

> **되돌리기 자체는 싸다. 비싼 건 "갈린 채로 오래 두는 것"이다.** NativeWind 5가 정식으로 나오면 **그때 올릴지 다시 판단한다** — 이 ADR을 대체하는 새 ADR로.
