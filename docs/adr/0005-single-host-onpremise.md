# ADR-0005 — 온프레미스를 단일 호스트로 전환한다

| | |
|---|---|
| 상태 | 채택 |
| 날짜 | 2026-09-10 |
| 대체 | 초기안 — Proxmox VE 8 · VM 다중화 · VLAN 4분리 (ADR 없음) |
| 관련 문서 | [tech.md](../tech.md) · [system-architecture](../diagrams/system-architecture.html) · [infra.md](../infra.md) |

## 맥락

배포 대상 하드웨어가 바뀌었다.

| | 초기안 | **실제** |
|---|---|---|
| 호스트 | Proxmox VE 8 | **Ubuntu 개인 PC** |
| RAM | **32 GB** | **8 GB** |
| SSD | 512 GB | 512 GB |
| NIC | 관리형 스위치 + VLAN | **1개** |

초기안은 **VLAN 4분리(DMZ · 앱 · 데이터 · 관리)** 위에 VM을 여러 대 올리는 구성이었다. 8GB에서는 하이퍼바이저 자체가 예산을 먹고, VM마다 게스트 OS가 또 먹는다.

## 검토한 대안

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| 초기안 강행 | 서사 유지 | **메모리 불가능** | ❌ |
| 클라우드 이전 | 자원 충분 | ⚠️ **"폐쇄망"이 주제인데 클라우드로 가면 주제가 사라진다** | ❌ |
| **단일 호스트 + Docker Compose** | 예산 안에 들어감 | **물리 격리 상실** | ✅ **채택** |

## 결정

> **하이퍼바이저를 버리고 Ubuntu 한 대에 Docker Compose로 전부 올린다. 격리는 물리에서 논리로 내린다.**

```
Ubuntu 24.04 (헤드리스) · 8GB · 512GB SSD
└── Docker Compose
    ├── net:dmz    cloudflared · nginx · tinyproxy
    ├── net:app    spring-app
    └── net:data   postgresql · redis     ← 호스트 포트 미노출
```

### 메모리 예산 — 이 결정의 실체

| 구성 | 평시 |
|---|---|
| Ubuntu(헤드리스) + Docker | 0.8 GB |
| PostgreSQL (`shared_buffers 256MB`) | 0.8 GB |
| Redis (`maxmemory 256MB`) | 0.4 GB |
| Spring Boot ×1 (heap 512MB) | 0.9 GB |
| nginx · cloudflared · tinyproxy | 0.13 GB |
| Prometheus · Grafana · Loki · Promtail | 1.1 GB |
| **합계** | **≈ 4.1 GB** (여유 3.9) |
| 앱 2대 시 | ≈ 5.0 GB |

> **여유가 필요한 이유는 PostgreSQL의 OS 페이지 캐시다.** 다행히 `trip_seat` 48만 행이 인덱스 포함 100MB 안쪽이라 통째로 캐시에 올라간다 — **8GB가 빠듯해 보여도 이 워크로드에는 충분하다.**

### 함께 정한 것

| 항목 | 결정 |
|---|---|
| 앱 대수 | **평시 1대 · 실증 시 2대** (`--scale app=2`) |
| **nginx** | **1대일 때도 앞에 둔다** — 나중에 붙이면 SSE 경로를 다시 검증해야 한다 |
| Ansible | **호스트 준비까지만** (Docker 설치 · `ufw` · 디렉터리) |
| 아웃바운드 프록시 | Squid → **tinyproxy** |

### 함께 폐기한 것

| 폐기 | 이유 |
|---|---|
| Proxmox VE 8 · VM 다중화 | 메모리 |
| **VLAN 물리 4분리 · 관리형 스위치** | NIC 1개 |
| step-ca | 내부 mTLS 대상이 없다 |
| 내부 레지스트리 · 의존성 미러 | 단일 호스트에 과잉 |

## 결과

| 얻은 것 | 잃은 것 |
|---|---|
| **추가 구매 0** | **물리 격리** — 논리 분리로 내려감 |
| 구성이 단순해짐 (Compose 하나) | 상시 이중화 |
| 헤드리스 운영이 강제됨 | **호스트가 죽으면 전부 죽는다** |

> **"폐쇄망"의 근거가 물리 분리에서 논리 분리로 내려간다.** 축소이므로 그대로 기록한다 — **VLAN을 쓴다고 써놓고 Docker 네트워크를 쓰면 그게 거짓말이다.**

⚠️ **GNOME이 1.5~2GB를 먹는다.** 데스크톱을 끄지 않으면 예산이 무너진다.

## 되돌린다면

| 항목 | 비용 |
|---|---|
| 여러 호스트로 확장 | **비교적 싸다** — Compose 서비스를 나누고 네트워크 이름을 유지하면 된다 |
| VLAN 물리 분리 복구 | 하드웨어 구매 · 재배선 |
| **비싼 이유** | 코드가 아니라 **하드웨어**다. 다만 **네트워크 이름(`net:dmz`·`net:app`·`net:data`)을 원래 VLAN과 1:1로 맞춰 뒀으므로** 나중에 물리로 승격할 때 이름은 그대로 쓴다 |
