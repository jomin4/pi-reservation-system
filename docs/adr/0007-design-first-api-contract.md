# ADR-0007 — API 계약을 손으로 쓴 `openapi.yaml`로 관리한다

| | |
|---|---|
| 상태 | 채택 |
| 날짜 | 2026-09-10 |
| 대체 | — (`tech.md` 초기 기록의 모호함을 해소) |
| 관련 문서 | [api.md §7 · 부록](../api.md) · [workflow.md §3](../workflow.md) · [deploy.md §6.1](../deploy.md) |

## 맥락

`tech.md` 초기 기록에는 **"API 문서 — SpringDoc OpenAPI"**만 적혀 있었다. SpringDoc의 기본 동작은 **코드에서 스펙을 생성**하는 것이다.

그 뒤에 정한 결정 셋이 그 전제와 충돌한다는 게 드러났다.

| 나중 결정 | code-first면 |
|---|---|
| `workflow.md` §3 **계약 PR이 구현 PR보다 먼저** | ❌ **코드가 먼저**여야 한다 |
| `deploy.md` §7.2 **생성 타입 최신성 검사** | ❌ 백엔드가 떠 있어야 스펙이 나온다 |
| `api.md` §7 **클라이언트 선행 개발** | ❌ 코드가 있어야 Mock이 뜬다 |

**네 트랙을 병렬로 개발한다**는 전제(`workflow.md` §1)에서 이건 치명적이다. 백엔드가 없는 동안 웹·모바일이 만들 근거가 사라진다.

## 검토한 대안

| 대안 | 계약 선행 | 클라이언트 선행 | 구현 검증 | 판정 |
|---|---|---|---|---|
| **code-first** (SpringDoc이 진실) | ❌ | ❌ | 불필요 | ❌ |
| code-first + **생성물 스냅샷 커밋** | ⚠️ **드러내기만** | ⚠️ 백엔드 이후 | 최신성만 | ❌ |
| **design-first** — 손으로 쓴 `openapi.yaml` | ✅ | ✅ | **CI diff** | ✅ **채택** |

## 결정

> **`docs/api/openapi.yaml`을 손으로 쓴다. 그게 계약의 진실이고, SpringDoc은 구현이 그걸 지켰는지 검증하는 데 쓴다.**

**Flyway와 같은 구조다.** 이 비유가 결정의 근거다.

| Flyway | OpenAPI |
|---|---|
| `V1__init.sql`을 **손으로 작성** | **`openapi.yaml`을 손으로 작성** |
| 앱이 기동 시 적용 | 백엔드가 그 스펙대로 구현 |
| **`validate-on-migrate`** — 이력 ↔ 파일 대조 | **CI diff** — 계약 ↔ SpringDoc 산출 스펙 |
| 어긋나면 **기동 거부** | 어긋나면 **CI 실패** |

**역할 분담**

| | 역할 | 진실인가 |
|---|---|---|
| **`docs/api/openapi.yaml`** | **계약** — 스키마 · 상태 코드 · 제약 | ✅ **진실** |
| **SpringDoc** | **Swagger UI** + **계약 대조용 산출 스펙** | 검증 대상 |
| **`api.md`** | **왜 그렇게 정했나** — `202`의 이유 · `409` 두 종류 | 의도 |

**양방향으로 잠근다**

```
        openapi.yaml (계약)
              │
    ┌─────────┴──────────┐
    ▼                    ▼
타입 생성 diff       SpringDoc 산출 스펙 diff
front · mobile CI        back CI
```

| 방향 | 어긋나면 |
|---|---|
| 계약 → 클라이언트 | **컴파일 실패** |
| 계약 → 백엔드 | **CI 실패** |

## 결과

| 얻은 것 | 잃은 것 |
|---|---|
| **백엔드가 한 줄도 없을 때부터 타입이 존재한다** | **계약을 손으로 써야 한다** |
| 클라이언트가 **처음부터 진짜 타입 위에서** 개발 | 계약 변경이 **두 곳**(yaml + 코드)을 건드린다 |
| **계약 선행 규칙이 기계로 강제된다** | `generateOpenApiDocs`가 CI에 한 단계 추가 |
| MSW fixture를 §5 예시에서 복사 — **새로 만들 게 없다** | |

**SSE는 예외다** — 스트림 프레임 구조는 OpenAPI로 표현하기 어렵다. **SSE 계약의 진실은 `api.md` §6**이고 yaml에는 엔드포인트와 미디어 타입만 적는다 (`api.md` 부록 A.5).

## 되돌린다면

| 항목 | 비용 |
|---|---|
| code-first로 전환 | yaml 삭제 · CI diff 검사 2개 삭제 |
| **함께 잃는 것** | ⚠️ **클라이언트 선행 개발** · 계약 선행 규칙의 강제력 |
| **비싼 이유** | 코드가 아니라 **개발 순서**가 바뀐다. 네 트랙 병렬(`workflow.md` §1)이 **백엔드 완료를 기다리는 직렬**로 되돌아간다 |

> **되돌리기가 비싼 건 파일 하나가 아니라 일하는 방식이다.**
