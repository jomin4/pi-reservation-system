# 코레일 인증 · 인가 조사

조사일 2026-09-04 · 대상 **코레일 단독**

## 목적

> 우리가 이미 내린 인증 · 인가 결정이 합리적인 축소인지, 그냥 누락인지 가른다.

`features.md`의 E · F · G 섹션(회원 · 인증 · 인가)을 확정할 때 이메일 인증 · 비밀번호 변경 · 비밀번호 재설정을 뺐다. 실제 예매 서비스가 어디까지 제공하는지를 대조해 그 결정의 근거를 남긴다.

| 구분 | 표기 |
|---|---|
| 확인 | 공식 안내 · 보도로 확인된 사실 |
| 추정 | 근거는 있으나 공식 확인 안 됨 |

---

## 1. 회원 인증

| 축 | 코레일 | 신뢰도 |
|---|---|---|
| 로그인 아이디 | **3종** — 코레일멤버십번호(기본) · 이메일 · 휴대전화번호 | 확인 |
| **가입 시 소유 증명** | **필수 아님.** 멤버십번호로만 쓸 거면 인증 불필요 | 확인 |
| 이메일 · 휴대폰 인증 시점 | 해당 값을 **로그인 아이디로 쓰겠다고 할 때만** 사전 인증 | 확인 |
| 외국인 | 여권 정보 + 이메일로 본인확인 | 확인 |
| 비밀번호 재설정 | 3단계 — 이름·회원번호 → **휴대전화 간편인증** → 새 비밀번호 | 확인 |
| 비밀번호 변경 | 마이페이지 → 휴대전화 또는 I-PIN 인증 후 | 확인 |
| 간편 로그인 | 코레일+ 앱 — PIN · 생체(지문 · 얼굴) | 확인 |
| **소셜 로그인** | **없음** | 확인 |

> **소셜 로그인 오해 주의** — 코레일은 네이버 · 카카오를 쓰지만 **계정 연동(federation)이 아니다.** 정부통합인증(Any-ID)의 **본인확인 수단**으로만 쓴다. 회원번호 · 비밀번호를 잊었을 때 기존 문자인증을 대체하는 용도이며, 로그인 계정 자체는 코레일이 보유한다.

**핵심** — 코레일은 **소유 증명을 가입의 전제로 삼지 않는다.** 이메일도 휴대폰도, 그걸 로그인 수단으로 쓰겠다고 할 때만 인증한다.

## 2. 채널별 비밀번호 이원화

이번 조사의 가장 중요한 발견.

| | 온라인용 | **현장용** |
|---|---|---|
| 쓰는 곳 | 홈페이지 · 코레일톡 앱 | **자동발매기 · 역 창구** |
| 형식 | 8자 이상 · 영문 + 숫자 + 특수문자 | **4자리 숫자** |
| 근거 기준 | 개인정보의 안전성 확보조치 기준 | — |
| 연동 | **없음.** 온라인 비번을 바꿔도 현장 비번은 안 바뀐다. 각각 따로 설정 · 변경 |

**분리한 이유** (공식 안내)

| 제약 | 내용 |
|---|---|
| 하드웨어 | 자동발매기 · 역창구 카드리더기가 **영문 · 특수기호를 지원 못 함** |
| 시간 압박 | 열차 출발시각이라는 제약이 있어 긴 비밀번호 입력은 이용자 불편이 큼 |

> **의도** — 이건 보안 설계가 아니라 **단말 제약에 맞춘 우회로**다. 대가로 사용자는 비밀번호를 2벌 관리하고, 한쪽만 바꿔 발권에 실패하는 사고가 실제로 보도됐다.

## 3. 비회원 처리

| 시점 | 방식 | 신뢰도 |
|---|---|---|
| ~2026-04-05 | 이름 + 휴대폰번호 + **임의 비밀번호 5자리** | 확인 |
| | 입력값은 **1회성 정보.** 통신사 진위 확인을 하지 않고 입력한 대로 받는다 | 확인 |
| **2026-04-06~** | 민간인증서 **간편인증**으로 전환 | 확인 |
| 조회 · 발권 | **예약번호 + 비밀번호 5자리** | 확인 |
| 제약 | 비회원 예약승차권 확인은 **역 창구 방문 필요** | 확인 |
| 명절 | **비회원 차단.** 회원번호 로그인 필수 (유량 제어 — [research.md](../research.md) 참조) | 확인 |

**핵심** — 비회원 조회의 열쇠가 **연락처가 아니라 예매 시 사용자가 정한 전용 비밀번호**다. 연락처는 알아낼 수 있지만 임의 5자리는 아니다.

## 4. 계정 보호

| 축 | 코레일 |
|---|---|
| **로그인 시도 제한** | **5회 오류 시 계정 잠금** |
| 잠금 해제 | 비밀번호 찾기 → 본인인증 → 재설정. 오류 카운트 초기화 |
| 2FA | 별도 제공 없음 (간편 로그인의 생체인증은 편의 기능) |

## 5. 우리 결정과 대조

> **2026-09-04 키오스크 채널 철회 반영.** 아래 대조는 철회 이후 기준이다. §1~§4의 코레일 실태 기록은 그대로 둔다.

| 우리 결정 | 코레일 | 판정 |
|---|---|---|
| 이메일 인증 없음 | **가입 시 소유 증명 필수 아님** | ✅ **근거 확보** |
| 소셜 로그인 없음 | 계정 연동 없음 (본인확인만 위탁) | ✅ 동일 |
| 2FA 없음 | 없음 | ✅ 동일 |
| **인증 시도 제한 — 5분 일시 차단** | **5회 영구 잠금** | ✅ 도입하되 **방식은 다르게** |
| 비밀번호 재설정 없음 | 있음 — 단 이메일이 아니라 **휴대전화 인증** | ⚠️ 축소 |
| 비밀번호 변경 없음 (`F-23` 철회) | 있음 | ⚠️ 축소 |
| **비회원 예매 없음** | **있음** (웹·현장 모두) | ⚠️ **축소 — 코레일과 갈리는 지점** |
| 로그인 아이디 = 이메일 1종 | 3종 (멤버십번호 · 이메일 · 휴대폰) | ⚠️ 축소 |

### 축소 3건에 대한 보충

**비밀번호 재설정 · 변경** — 뺀 이유를 "이메일을 못 보내서"로 적었었는데, **코레일은 애초에 이메일이 아니라 휴대전화 인증을 쓴다.** 우리가 못 하는 진짜 이유는 이메일이 아니라 **본인확인 수단이 아무것도 없다는 것**이다.

**비회원 예매** — 코레일은 웹에서도 비회원 예매를 지원한다. 우리는 키오스크 철회와 함께 이것도 뺐다. 그 대가로 **인증 경로가 JWT 하나뿐**이 되어, 원래 이 조사의 동기였던 "인증 방식이 다른 채널을 하나의 Principal로 환원한다"는 주제가 사라졌다.

## 6. 시도 제한 — 코레일을 그대로 베끼면 안 되는 이유

이 조사에서 실제로 설계에 반영된 유일한 항목이다.

| | 코레일 | 이 프로젝트 (`F-36`) |
|---|---|---|
| 임계 | 5회 | 5회 (동일) |
| 조치 | **영구 잠금** | **5분 일시 차단 후 자동 해제** |
| 해제 수단 | 비밀번호 재설정 + 본인인증 | 시간 경과 |

> **의도** — 코레일은 잠기면 재설정으로 푼다. **우리는 재설정이 범위 밖이라 잠기는 순간 계정이 영구 사망한다.** 같은 임계값을 쓰되 조치는 반드시 시간 기반이어야 한다. 부수적으로 **자동화된 반복 로그인이 자기 계정을 잠그고 죽는 사고**도 막는다.

---

## 7. 이 조사가 설계에 남긴 것

| 항목 | 결과 |
|---|---|
| 이메일 인증 없음 | ✅ **근거로 채택** — 코레일도 가입 전제로 삼지 않는다 |
| `F-36` 인증 시도 제한 | ✅ **신규 기능으로 추가** (P1). 단 조치는 시간 기반으로 변형 |
| 예약번호를 무작위로 | ✅ 반영 — 순번이면 누적 건수가 노출된다 |
| 채널별 비밀번호 이원화 | ❌ 도입 안 함 — 현장 단말이 없어 문제 자체가 사라졌다 |
| 조회 PIN 체계 | ❌ **2026-09-04 철회** — 비회원·비로그인 조회가 사라졌다 |

> **철회된 것도 기록으로 남긴다.** 조회 PIN은 코레일의 비회원 5자리 비밀번호를 근거로 도입했다가, 키오스크 철회로 함께 사라졌다. 근거가 옳았어도 전제가 바뀌면 결론이 바뀐다는 사례다.
