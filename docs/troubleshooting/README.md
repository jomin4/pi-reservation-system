## 언제 쓰나

**두 질문에 "예"면 쓴다.**

| # | 질문 |
|---|---|
| ① | **원인이 자명하지 않았나?** — 30분 이상 헤맸거나, 에러 메시지가 원인을 안 가리켰다 |
| ② | **다시 만날 것 같은가?** — 나 또는 **다른 트랙 세션**이 |

**안 쓰는 것** — 오타 · 문서를 읽으면 아는 것 · 일회성 환경 사고.

> **네 트랙이 각자 Claude 세션으로 병렬 개발한다**(`workflow.md` §1). 세션끼리는 직접 소통하지 않으므로, **한 세션이 겪은 문제가 다른 세션에 닿는 유일한 통로가 이 폴더**다.

## 검색되게 쓴다

> **트러블슈팅은 읽는 문서가 아니라 찾는 문서다.**

| 규칙 | 이유 |
|---|---|
| **에러 메시지를 원문 그대로** | 나중에 **그 문자열로 검색**해서 도달한다 |
| 제목은 **원인이 아니라 증상** | 겪을 때는 원인을 모른다 |
| 파일명 `YYYY-MM-DD-슬러그` | 시간순 정렬 · 언제 겪었는지가 이름에 |

**나쁜 제목** — `Flyway 설정 오류` · **좋은 제목** — `앱이 기동하다 Detected applied migration not resolved locally 로 죽는다`

## 상태 값

| 값 | 뜻 |
|---|---|
| **해결** | 근본 원인을 고쳤다 |
| **우회** | ⚠️ **원인은 그대로.** 피해 갔을 뿐 — **다시 만난다** |
| **미해결** | 아직 못 풀었다. 기록만 |

> **`우회`를 정직하게 표시한다.** 나중에 같은 증상을 만났을 때 "해결"이라고 적힌 문서를 믿고 갔다가 다시 막히는 게 가장 나쁘다.

## ADR과의 경계

| | ADR | **트러블슈팅** |
|---|---|---|
| 다루는 것 | **결정** | **문제** |
| 시점 | 하기 **전** | 겪은 **뒤** |
| 질문 | 왜 이렇게 정했나 | **왜 안 됐고 어떻게 풀었나** |
| 불변인가 | ✅ 불변 | ❌ 갱신 가능 |

> **해결책을 찾다가 설계를 바꾸게 됐다면 ADR도 함께 쓴다.** 그때 트러블슈팅 문서는 그 ADR의 **맥락**이 된다.

## 쓰는 법

3. **이 파일의 목록에 한 줄 추가**
4. 커밋 — `docs(troubleshooting): <증상>`

## ⚠️ 「막다른 길」 절을 비우지 말 것

템플릿의 **막다른 길**이 이 폴더의 값을 절반 이상 만든다.

> **대부분의 트러블슈팅 노트는 해결책만 적는다.** 그래서 다음 사람이 **똑같이 실패한 경로를 다시 밟는다.** 무엇이 아니었는지가 무엇이었는지만큼 중요하다.
